## Why

An idea that never becomes a frozen, attributable snapshot is already lost: the source issue can change, a URL is not evidence, and a GitHub App that only lists repositories cannot tell a team *what intent* was considered. The board now exists, and its Idea lane is empty by construction — `workflow-board-ui` ships a provider that returns no cards, a listener line reading *not configured*, and Load ideas and Compose controls disabled with the reason "Idea intake is not enabled for this installation yet." This change is the first backend behind that surface. It captures Ideas with provenance, so the Idea lane reports real work instead of explaining its own absence, and so later attended launches and Promote inherit an Idea that already carries a snapshot.

## What Changes

- Add **read-only MCP inboxes** for GitHub Issues, GitLab issues, and Jira, plus a **local manual inbox**, all scoped to the current GitHub App installation from `github-app-installation`.
- **Saved Ideas appear as Idea-lane cards on the existing board.** The board's provider fills the Idea lane from stored Ideas and their latest snapshots. There is no intake page, no saved-ideas list, and no intake route: the four lanes are the host surface.
- **Load ideas is the board's own control**, on the Idea lane header and in the toolbar. Each invocation reads **exactly one** inbox — one menu option per configured connector, plus Manual — and opens a **candidate review sheet** holding at most 50 candidates per read, most recently updated first, saying so when the source has more. Nothing is stored until the reader chooses Save; closing the sheet discards every unsaved candidate. Choosing Manual re-reads the local store and opens no sheet.
- **Saving** a candidate creates an immutable snapshot (normalized fields, content hash, fetch time, adapter identity and version, canonical permalink when imported). The client sends only the inbox and the external id; the **server re-reads the item** so imported content never arrives from the browser. Saving an already-saved external id appends a snapshot to the same Idea.
- **Refresh** of a saved imported Idea creates a **new** snapshot and MUST NOT rewrite earlier rows, including any snapshot later selected for promotion.
- **Compose is the existing compose dialog plus a persist route.** No second form: the board supplies the dialog's handler, the provider flips compose to available, and the server validates with the same pure functions the dialog uses, so client and server cannot drift.
- **Provenance, Refresh, Remove and interpretation live in a new "Snapshot provenance" section of the existing detail panel** — not in its overflow menu, which stays at Copy link / Open source / Hide. Remove is a shared server-side soft delete; Hide stays this viewer's local, reversible view state. The two are named as different operations everywhere they appear.
- **Connector health feeds the existing source-health panel, the source status banner, and the Settings "Source connections" list.** One row per configured connector, with a Retry that re-reads that one inbox, saves nothing, and shows no candidates. No surface anywhere offers credential entry, login, OAuth, or connection editing.
- Run an **Idea-lane listener every five minutes** over every configured inbox of an installation, recording last attempt, last success, consecutive failures, and bounded backoff. Its state **replaces the lane's `not-configured`** whenever the listener host is enabled and the installation has at least one configured connector. The listener never auto-saves: Ideas appear only on explicit Save or Compose.
- Treat imported bodies as **untrusted data**: store the adapter-normalized payload as retrieved, hash it once at insert, and render it on every surface — card, detail, candidate row, interpretation — as **literal text**. No sanitizer, no markdown rendering; markup appears as its literal characters, and an imported address becomes a link only through the existing http/https safe-link allow-list. Imported text never selects an installation, inbox, repository, or filter.
- **Never write** comments, labels, transitions, assignments, or any other mutation to GitHub Issues, GitLab, or Jira.
- Isolate Ideas and snapshots by **installation**. Installation A's snapshots never appear in B, and a foreign or unknown Idea id is indistinguishable from one that does not exist.
- Retain snapshots under **two 90-day clocks, never stacked**: a superseded snapshot may be hard-deleted 90 days after its capture, and a removed Idea's snapshots 90 days after the removal. The latest snapshot of a live Idea and any snapshot selected for promotion are never hard-deleted. Saving a source item whose Idea was removed **restores that Idea** rather than creating a second one.

Out of scope: GitHub branch, commit, or pull-request writes; attended Interlock launches; PR/MR fetch; workflow projection; webhooks; an MCP-to-GitHub identity join beyond a per-installation connector; OpenSpec discovery re-classification; any credential-entry or connection-editing surface; and the prototype's assignee filter and repository-required compose fields, which the board and compose specs already exclude.

## Capabilities

### New Capabilities

- `idea-intake`: Select configured inboxes, a five-minute Idea-lane listener with reported state, Load ideas for one inbox at a time, candidate review before saving, manual compose, Ideas presented as Idea-lane cards, and inbox connection health — all scoped to one installation.
- `source-provenance`: Immutable snapshots and content hashes, permalink versus manual labeling, snapshot history and interpretation kept apart, untrusted-content rules, no source write-back, tenancy isolation, and retention and deletion.

### Modified Capabilities

- None. This change **consumes** and never modifies the living specs `github-app-installation` (installation tenancy, the GitHub session, and the repository rows it already stores) and `openspec-discovery` (both archived 2026-09-19), and the capabilities introduced by the four unarchived UI changes — `design-system` and `app-shell` (`design-system-and-app-shell`), `workflow-board` (`workflow-board-ui`), `card-detail` and `source-health` (`card-detail-and-source-health-ui`), and `compose-idea-dialog` and `promote-dialog` (`handoff-flow-dialogs-ui`). None of them receives a delta here; how each is consumed is recorded in `design.md`.

## Impact

- **Apply-order prerequisite:** `design-system-and-app-shell` → `workflow-board-ui` → `card-detail-and-source-health-ui` → `handoff-flow-dialogs-ui` → this change. All four UI changes must be applied first. This deliberately differs from the epic's order, which puts intake second and the board fifth: the four UI changes were pulled ahead so that the board exists as an honest, provider-driven surface before any backend fills it. Intake is therefore the first backend *behind* the board rather than a surface of its own, and the board's own Forward notes assign this work here.
- **Sibling-owned files, edited additively:** `src/server/board/board-view.ts` (owned by `workflow-board-ui`) calls the two new board modules; `src/lib/board/card-detail-view-model.ts` (owned by `card-detail-and-source-health-ui`) gains exactly one optional member; `src/app/components/detail/detail-panel.tsx` (same owner) renders the provenance section when that member is present; `src/app/components/board/board-screen.tsx` (owned by `workflow-board-ui`) gains exactly one optional `revealCardId` prop, so the card a compose just created can be selected — the screen sets selection only at initialization, from `?card=`. Each edit adds and never rewrites. One sibling-owned **test** edit is declared rather than hidden: `src/server/board/board-view.test.ts` has only its assertions about the Idea lane's cards, listener state and manual-read options, about compose, and about source health updated — the behavior that sibling's own Forward note assigns here — with no assertion deleted without a replacement and every other assertion passing unmodified. `src/app/page.tsx` renders the client wrapper that supplies the board's manual-read, pending, and compose handlers, and `src/server/env.ts` gains two flags; both are app-level rather than sibling-owned.
- **New code:** one migration (`migrations/0003_idea_intake_schema.sql`, four tables), four repository modules under `src/server/db/`, the adapter port and adapters under `src/server/intake/`, two framework-free modules under `src/lib/intake/`, two board provider modules under `src/server/board/`, seven local-write API routes under `src/app/api/ideas/`, the intake client components under `src/app/components/intake/`, the listener host in `src/instrumentation.ts`, and a `/dev/ui/intake` preview page with its fixtures.
- **Dependencies:** one new runtime dependency, the MCP client SDK, with the exact version resolved from the registry at install and pinned literally per CLAUDE.md. Not added: a markdown sanitizer (unnecessary once imported text is literal text) and a scheduler (the listener host is one in-process timer).
- **Environment:** two new variables. `JUMPHOUR_IDEA_LISTENER=1` enables the listener host, default off everywhere; `JUMPHOUR_INBOX_CONNECTORS_FILE` names an operator-managed JSON file outside git that declares each installation's connectors. Each connector names the *environment variable* holding its secret, so no secret is stored in SQL, in the file, or in git. With neither variable set, an installation has zero connectors: intake is Manual-only and the Idea lane honestly reports *not configured*.
- **Source writes:** zero GitHub/GitLab/Jira writes. The adapter port has no write member and a recorder asserts it, extending CLAUDE.md's GitHub rule to the other two sources. The new API routes write only Jumphour's own SQL store.

**Assumptions:**

- Tenancy key is `github-app-installation`'s **`installation_id`** (workspace 1:1 with installation). Do not invent a second workspace table.
- MCP credentials in V1 are a **per-installation connector**, declared by an operator in a file and resolved from named environment variables — no connection UI, no credential entry, no OAuth wizard anywhere in the product. Any signed-in user of that installation may Load or be served by the listener. Per-user OAuth and a GitHub-to-Jira identity mapping stay deferred (epic Q12).
- **Import without a repository or a Promote path is allowed** (epic Q13). Jumphour never assigns an owner, so Idea cards carry no repository and no owner.
- Manual schema is **title + description** (required) and optional supporting links — not the design prompt's required repository or suggested owner. The compose dialog already renders exactly these fields.
- Retention is a V1 default of **90 days**, counted from capture for a superseded snapshot and from removal for a removed Idea's snapshots. There is no "view" clock: card detail ships inside the board view model, so the server never observes a view and `last_viewed_at` does not exist. A live Idea's latest snapshot, and any snapshot selected for a promotion, are never hard-deleted.
- External adapters may be `available`, `unavailable`, or `misconfigured` at runtime — those are the only three, and there is no separate "unauthorized" state. `unavailable` is **every failed read**, including a credential the source rejects, so Retry stays available and the connector recovers by itself on the next successful read. `misconfigured` is **structural only**, decided when the connector file is mirrored (malformed entry, unset credential variable, duplicate entry), and needs an operator. Both display as *unreachable* plus one reason sentence. Manual always works. Do not claim production MCP servers are deployed.
- Load ideas → Manual re-reads the **local** store and creates nothing. **Compose** is the only create path for manual Ideas.
- The board's Load ideas menu sentence — "Reads the selected source now and captures snapshots. Never writes back." — is owned by `workflow-board-ui` and is **not** edited here. The candidate review sheet's own subline, "Read just now. Nothing is saved until you choose Save. Never writes back.", is what makes the flow truthful, because capture happens at Save.

**Deferred:** MCP per-user OAuth and identity join, Promote-linked snapshot selection beyond the forward constraint that the promote handler sets the promotion snapshot at submit time, session-artifact adapters, and the evidence-derived projection that will eventually move promoted Ideas out of the Idea lane.
